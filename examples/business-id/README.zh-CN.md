# 发布单关联

为发布单的每次评估分配一个业务编号，将它与不可变的 Run 关联。管理员配置场景并发布策略；调用方携带业务编号创建 Run、提交观测，再按编号查询决策、冻结策略和证据。本示例不执行发布或部署操作。

```sh
make build
python3 -B examples/business-id/smoke.py
```

示例启动真实的临时 SQLite 服务，通过 CLI 创建、查询、提交和导出报告，验证中文与特殊字符、凭据保留、内容冲突、场景隔离、8 路并发、完成及过期后的查询、报告关联。退出时删除临时数据和合成凭据。完整质量门禁还通过共享后端测试验证数据库事务语义。

实际接入时，可使用 `release-42/batch-1/attempt-1` 作为一次评估的编号，重试保持编号不变，发布单上下文放在 `changeSet` 中。通过 `run list --scene SCENE --business-id ID` 或控制台 Runs 页面的业务编号筛选找到记录，进入详情查看冻结策略、最终证据和决策，再由执行侧核验后操作。

业务编号在项目、场景内唯一，精确匹配，不能含首尾空白或 ASCII 控制字符，长度为 1–128 个 UTF-8 字节。省略参数保留原有行为，显式空值无效。不指定场景查询时，可能匹配多个场景中的相同编号。

同编号、同内容重放原 Run；不同内容返回 `BUSINESS_ID_CONFLICT`。重放返回退出码 5，提示原 Run ID，不重新签发凭据，也不覆盖已有文件。先检查已保存的凭据，仅在 OPEN Run 的凭据丢失时轮换；轮换会使旧凭据失效。完成或过期不释放编号，新评估需要新编号。

业务编号用于关联，不代表执行授权。Run 响应和排障报告包含该编号，不要使用秘密信息作为编号，分享报告前检查内容。
