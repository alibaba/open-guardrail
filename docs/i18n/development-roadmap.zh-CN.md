# 开发路线图

本文为仓库内贡献者文档，不在产品站发布；与[英文源码](../development-roadmap.md)一同维护，结构和示例由网站检查覆盖。本路线图区分已经实现的能力和后续产品工作。阅读入口见[文档目录](../README.md)；[基线 ADR](../adr/0001-product-baseline.md)记录了最初的设计背景。

## 开发预览版已具备的能力

| 领域 | 已实现的行为 |
| --- | --- |
| 服务与存储 | 原生服务与 CLI；严格配置校验；SQLite / PostgreSQL 初始结构，支持外部预建结构模式；就绪检查，以及版本和能力发现 |
| 身份 | 本地管理员初始化和恢复、浏览器 / CLI 会话，以及限定 Project 范围、有有效期限制、支持元数据查询、轮换和撤销的机器密钥 |
| 策略管理 | 精确资源绑定、固定 / 激活修订选择及审计；Scene、可编辑的草稿修订、不可变的已发布修订、按已审阅草稿发布、激活和有界修订历史 |
| 评估 | 独立 Run；不可变的修订引用和上下文；完整的中间 / 最终快照；结构化证据；固定的 Result / Decision 汇总规则；惰性过期处理和决策有效期 |
| 机器集成 | 根据 OpenAPI 生成的 HTTP 客户端、限定 Run 范围的提交凭据、修订和已存储 Submission 的读取接口、有界 Run 列表及端点范围授权 |
| 用户界面 | 内置管理员初始化页面、策略管理页面、只读 Run 检查页面、项目审计查询和结构化诊断导出 |
| 示例与打包 | 使用合成观测的本地 Agent、Jenkins 和 Argo Rollouts 示例；原生二进制归档；可选的 HTTPS 反向代理后 Docker Compose 部署 |

另见[当前限制](../../README.md#current-capabilities-and-limits)和[参考集成状态](../../integrations/README.md)。

## 尚待完成的产品工作

1. **执行控制。** 定义并实现 Claim、执行尝试、ActionResult 和人工处置。在每次状态转换中保持决策有效期、幂等性、授权和审计要求。
2. **评估器身份。** 建立进程外评估器的注册与鉴证机制，明确证据接受条件，以及调用系统对证据的核验责任。
3. **公开组合与 Provider。** 一并交付服务端组合 API、首个可替换的身份 / Provider 契约、默认实现和独立 Go 模块消费示例。当前目录中的设计 README 尚不构成受支持的 Go API。
4. **共享部署保证。** 在对外承诺多实例运行之前，验证 PostgreSQL 的跨进程并发与恢复能力；继续明确 SQLite 的单实例边界。
5. **运维完整性。** 扩充审计覆盖、保留策略、可观测性和受支持的导入 / 导出接口，同时提供对应的用户指南和 CLI 入口。
6. **更多交付示例。** 实现并验证 GitHub Actions 和 Argo CD 同步钩子接入方案；现有 Jenkins 和 Argo Rollouts 示例继续明确标注使用合成观测。

[扩展指南](../extensions.md)定义了预期的 Provider 边界。组织专属适配器应消费公开契约，并保持共同的策略、证据和决策语义。私有 SDK 和部署约定应留在导出的公共核心之外。

## 每项能力的一致性要求

每个端到端能力切片都必须提供相匹配的 SQLite 和 PostgreSQL 迁移，并在两种驱动上验证相同的可观测 API、状态机及错误行为。变更需要按适用范围提供幂等性、并发写入、过期、凭据隔离、回滚和必要审计记录的验证证据。除了 HTTP 契约，还必须提供受支持的 CLI 和有文档说明的端到端用法。

当前预览版仍声明 `multiInstance: false`。一次成功连接或单进程测试不能证明跨进程保证。后续执行控制还需要验证 Claim 的独占性，以及 ActionResult 的终局性。

## 生产可用性

生产采用还需要存储后端的并发与恢复证据、SLO / 容量验证、备份恢复演练，以及对部署中身份、访问控制和证据核验边界的审查。从其他实现迁移时，还需要外部行为差异测试。这些要求不意味着要给 Go 核心增加另一套运行时，也不构成提供公共 SDK 的承诺。
