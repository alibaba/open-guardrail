# 规划你的首次接入

从一个操作、一组明确的检查，以及能够在行动前核验决策的执行工具开始。同一份评估契约将策略、观测和执行流程连接起来。

## 选择能够观测的操作

| 起步场景 | 可以定义的检查 | 从哪里开始 |
| --- | --- | --- |
| 文件清理 | 精确目标文件、临时文件范围和每批数量 | [快速开始](../getting-started.md)中的真实文件清理示例 |
| 应用交付中的一个步骤 | 目标应用与环境、必需的测试或健康观测 | [集成指南](../../integrations/README.md)及其中的合成观测交付示例 |
| 配置或数据操作 | 预期资源范围、业务规则要求的观测 | [GuardrailSpec 参考](../guardrailspec-reference.md)与 [HTTP API](../api.md) |

首次接入时，选择工具能够收集观测、执行方能够核验证据的检查项。文件清理 Demo 提供了可完整查看的本地示例，便于在连接其他系统前熟悉流程。

## 连接三类职责

1. **策略维护方：** 发布 GuardrailSpec，选择 Scene 的激活策略。
2. **Agent 或评估器：** 读取要求、执行检查，使用 Run 的提交凭据提交完整结果和证据。
3. **执行工具：** 读取权威 Run，确认操作上下文、决策有效期、已接受证据及当前目标，再应用自身权限执行操作。

OpenGuardrail 根据策略校验评估并记录决策；观测和执行集成负责连接真实系统。读取和重试流程见 [Run 与 Submission](../runs.md)。

## 选择部署方式

| 用途 | 存储与设置 |
| --- | --- |
| 本地体验 | 使用原生二进制或源码构建，以 SQLite 启动服务，或运行一次性文件清理 Demo。 |
| 共享并保留评估记录 | 配置 PostgreSQL，每个数据库运行一个服务实例。 |
| 提供远程访问 | 将服务置于可信 HTTPS 代理之后，配置管理员和机器凭据。 |

具体设置见[配置与存储](../configuration.md)、[Docker 部署](../docker.md)及[管理员初始化](../local-administrator.md)。

## 体验完整闭环

运行示例，检查拒绝与放行两次评估，在控制台读取被接受的证据。然后将示例策略和观测来源替换为自己的操作要求。

当前发行状态为开发预览，HTTP API 为 `v1alpha1`。使用文档说明的单实例部署方式，升级版本时核对 API 契约。
